# OwnerWeb 设计说明

> 本文档不是重新写 PRD，而是把页面结构、交互流程和视觉规则讲清楚，方便后续 AI 或开发者继续写代码时对齐设计。

## 1. 设计来源

当前没有独立的 `design/` 原型目录，已实现页面就是设计基准。

主要视觉与布局代码：

- `src/styles/global.css`：全局视觉体系、组件样式、响应式规则。
- `src/components/`：首页区块、视觉背景、交互组件、表单和后台内容组件。
- `src/data/resume.js`：静态兜底文案、项目种子和兜底数据。

后续新增页面时，优先复用现有 `PageShell`、`SectionHeading`、`btn`、`field`、`tabs`、`comment` 等组件和样式类。

## 2. 视觉方向

关键词：

```text
深色科技 / 工程感 / 高对比 / 大幅留白 / 嵌入式硬件主题
```

核心视觉规则：

- 主背景为近黑 `#0a0a0a`。
- 主强调色为红色 `#ff3b30`，用于编号、按钮、高亮和交互状态。
- 文字主体为高对比白灰，辅助文字使用低饱和灰。
- 标题使用 `Space Grotesk` / `Inter` 气质，正文使用系统中文友好字体。
- 技术编号、标签和辅助信息使用 `JetBrains Mono` / monospace。
- 导航栏品牌标记使用内联 SVG“芯片 + 电路走线”图标，不含文字字母：自带近黑圆角底板、白色芯片轮廓与走线、红色信号焦点；标记容器不再叠加红色渐变底色，改为细高光描边加红色光晕阴影，悬停时轻微上移；站点 favicon 复用 `public/brand-icon.svg`。
- 个人介绍页头像卡内为 **three.js 渲染的真实金属硬币**（`src/components/Portrait3D.jsx`，@react-three/fiber）：程序化环境贴图产生真实镜面反射，`LatheGeometry` 做圆角倒角；币面绘制 `LH`、`LI HAORAN`、`EMBEDDED · 2026` 与白色外环。反光质感对齐首页 PCB 的 PBR 材质，不再是 CSS 假高光。
- 硬币交互：悬停上半部分上仰、下半部分下俯；悬停左半持续向左旋转、右半持续向右旋转；鼠标拖拽跟随旋转；移出硬币后回正到初始朝向，静止时轻微浮动；`prefers-reduced-motion` 下降低动效。
- 头像卡背景为向内挖空的矩形腔体（保留原有空间感）：整个卡片即开口，四壁为光影渐变平面，腔底为深色背板与微弱红色环境光；硬币悬浮于腔体中央；`portrait-media` 使用 CSS 渐变作底，不再引用位图背景。
- 首页使用 Three.js、OGL、Aurora、Ghost Fibers 等视觉组件营造硬件与信号流动感。
- 版心最大宽度约 1700px，适合大屏展示。
- 卡片和按钮有轻微玻璃感、细边框和柔和阴影。
- 动效以 reveal、hover、微位移和背景流动为主，避免喧宾夺主。
- 首页主要区块使用适中的上下留白，避免经历、精选项目、个人优势和联系区之间出现大面积断层；移动端同步收紧间距但保留内容呼吸感。
- Hero 首屏按视口尺寸自适应：PCB 模型、上下内边距和移动端快速导航随视口高度缩放，确保桌面端、平板端和移动端的首屏内容完整可见。
- Hero 副标题下方居中显示红色 `SCROLL TO EXPLORE` 提示，动态箭头位于文字正下方，点击后定位到个人经历区块；减少动效模式下停用箭头动画。
- Hero 内容在首屏内垂直下移少许，PCB 模型适度放大；低高度屏幕使用独立尺寸上限，避免模型或文字超出可视区域。
- Hero PCB 与下滑提示分层错开：PCB 视觉位置略向下，下滑提示略向上，避免个人经历热点标注与提示内容互相遮挡。
- Hero 响应式布局：桌面端采用左侧文字、右侧 PCB 的双栏结构；平板和移动端切换为标题、PCB、下滑提示和快速导航的上下结构。
- 桌面端 Hero 标题前后两段分别独占一行，PCB 作为右侧主视觉放大展示；`SCROLL TO EXPLORE` 固定在 Hero 左下方，窄屏恢复为内容流中的提示。
- PCB 放大通过 Three.js 相机取景范围实现，不扩大外层画布；桌面端标题顶部独立对齐，避免随模型高度变化而下移。
- 桌面端标题保留轻微下移微调，PCB 继续通过相机取景放大，同时为热点标注保留横向安全边界。
- 桌面端左侧文字区域为左下角下滑提示预留底部空间，PCB 取景保持热点文字完整可见，避免提示与标题重叠。
- PCB 本体采用独立 `1.35x` 缩放，热点引线和文字保持独立取景并重新连接到放大后的板面边缘，兼顾模型清晰度与提示完整性。
- PCB 本体缩放调整为 `1.2x`，热点文字平面放大并关闭深度遮挡，确保文字和引线清晰显示在模型上方；桌面端标题继续下移 `20px`。
- 桌面端 PCB 外层模型容器向左扩展 `10px`；五组热点引导线分别连接到对应白色虚线框边缘，而不是连接到开发板本体边缘。
- PCB 整体保留旋转安全边界；白色虚线框、引导线、端点和提示文字使用同一悬浮层级，形成统一的标注组件。
- PCB 翻转交互中，正面引导线和提示文字保持前方悬浮；白色虚线框只属于 PCB 正面，转到背面时隐藏。
- PCB 转到背面时，正面引导线和提示文字与白色虚线框同步隐藏；精选项目引线起点与对应虚线框略有重叠，避免出现视觉断点。

## 3. 响应式断点

当前样式断点：

- Desktop: 大于 `1080px`
- Tablet: `680px` 到 `1080px`
- Mobile: 小于 `680px`

移动端要求：

- 导航、标题、项目卡片和表单必须完整换行。
- 不允许文字溢出按钮或卡片。
- 视觉背景不能影响正文可读性。
- 视频区域保持稳定宽高，不能挤压布局。

## 4. 页面与路由

```text
/                首页
/experience      个人经历
/projects        精选项目
/projects/:id    项目详情
/strengths       个人优势
/comments        访客留言
/auth            登录 / 注册
/settings        账号设置
/admin           管理后台
```

## 5. 首页交互

- 顶部导航切换核心区块和独立页面。
- 首页 PCB 热点跳转到区块时，按对应区块标题定位在固定导航栏下方，避免标题和首屏内容被遮挡。
- Hero 展示职业定位、主标语和主要行动入口。
- Hero 和联系区内容来自 `ContentProvider`，初始化保留静态兜底，接口成功后读取 `site_content`。
- 点击项目卡片进入项目详情页。
- 滚动进入区块时执行 reveal 动画。
- 联系区展示电话、邮箱、GitHub 和微信等联系信息。

## 6. 项目详情页交互

- 项目列表由 `ContentProvider` 提供：初始化时保留静态兜底数据，`GET /api/projects` 成功后切换为数据库数据。
- 后台保存、上传或删除项目后，会同步刷新 `ContentContext`；同一次 SPA 会话内进入前台项目页即可看到最新数据。
- 前端路由切换时会重新请求动态项目数据，避免后台变更后长时间显示旧内容。
- 根据 URL 中的 `id` 从动态项目列表查找项目；接口不可用时继续可查看兜底项目。
- 未知 `id` 显示“未找到该项目”。
- 展示项目标题、英文名、定位、技术标签、演示视频、长介绍和核心实现。
- 有上传封面时视频使用封面作为 poster；没有视频时显示“该项目还没有上传演示视频”。
- 外部仓库链接使用新标签打开。
- 底部展示当前项目的多级评论。
- 返回按钮回到 `/projects`。

## 7. 个人经历页交互

- 个人身份、教育背景、联系方式和专业认证读取 `site_content.profile`。
- 经历简介和统计读取 `site_content.experience`。
- 联系列表根据数据库中的邮箱、电话、微信、GitHub 和所在地生成。
- 接口不可用时继续显示 `resume.js` 中的兜底内容。

## 8. 登录注册页交互

- 登录与注册使用分段式标签切换。
- 注册需要昵称、邮箱、密码和确认密码。
- 密码和确认密码支持显示 / 隐藏切换，按钮使用眼睛 / 闭眼图标，不用文字按钮。
- 两次密码不一致时给出前端错误。
- 登录或注册成功后跳转 `/settings`。
- 请求失败时展示后端错误信息。

## 9. 账号设置交互

- 未登录时提示先登录，不渲染资料表单。
- 支持上传头像，成功后刷新用户上下文。
- 支持修改昵称，不提供个人签名维护。
- 支持修改密码，需要原密码和两次新密码。
- 保存成功显示确认提示，失败显示错误提示。

## 10. 留言区交互

访客留言：

- `/comments` 使用 `GuestbookComments` 组件。
- 未登录时显示“登录后参与留言”，并提供登录入口。
- 登录后可提交顶层留言，也可回复已有留言。
- 有头像的用户在留言和回复中显示当前头像；未上传头像时显示昵称首字。
- 提交成功后清空输入并刷新留言列表。
- 空状态使用友好文案。

项目评论：

- 项目详情页使用 `ProjectComments(projectId)` 组件。
- 评论头像读取用户当前 `avatar`，头像更新后同一用户的评论立即显示新头像。
- 登录后可提交顶层评论。
- 每条评论都有“回复”入口，可以回复任意层级评论。
- 前端根据 `parent_id` 递归渲染评论树，子评论使用缩进和虚线层级线。
- 回复表单只在当前被回复的评论下方展开。
- 提交成功后清空回复内容并刷新评论树。

## 11. 管理后台交互

- 非管理员只能看到无权限提示。
- 内容管理、评论管理、项目管理和用户管理使用标签切换。
- 评论列表显示来源位置：访客留言或具体项目名。
- 删除访客留言或项目评论时，会连同其子回复一起删除。
- 删除评论后重新加载评论列表。
- 项目管理支持新增、编辑和删除。
- 项目管理标题栏保持标题单行显示；“新增项目”“保存项目”等操作按钮按内容自适应宽度，移动端允许按钮换行但不撑开标题。
- 删除项目时先显示确认条，提示会同时删除该项目全部评论；确认后删除并刷新列表。
- 项目编辑区分为基本信息、展示与链接、视频与封面。
- 老项目在未上传封面时继续使用内置 SVG 封面；上传封面后项目卡片显示真实图片。
- 上传项目视频或封面成功后刷新后台列表，并保留在当前编辑状态。
- 内容管理支持编辑 Hero 文案、身份与联系信息、教育与认证、经历简介和经历统计。
- 保存内容后同步刷新 `ContentContext`，前台首页、经历页、联系区和搜索立即使用新数据。
- 用户操作包括设为管理员、设为普通用户、封禁、解封、删除。
- 当前删除操作没有二次确认，这是待补强交互。

## 12. 个人优势页交互

- 优势列表由 `ContentProvider` 提供：初始化时保留静态兜底数据，`GET /api/strengths` 成功后切换为数据库数据。
- 每条优势的编号由排序值生成，列表按排序值展示。
- 后台“优势管理”支持新增、编辑、删除和调整排序。
- 删除优势前显示确认条；确认后刷新后台列表和前端内容上下文。
