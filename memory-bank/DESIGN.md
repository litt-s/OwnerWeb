# OwnerWeb 设计说明

> 本文档不是重新写 PRD，而是把页面结构、交互流程和视觉规则讲清楚，方便后续 AI 或开发者继续写代码时对齐设计。

## 1. 设计来源

当前没有独立的 `design/` 原型目录，已实现页面就是设计基准。

主要视觉与布局代码：

- `src/styles/global.css`：全局视觉体系、组件样式、响应式规则。
- `src/components/`：首页区块、视觉背景、交互组件和表单。
- `src/data/resume.js`：文案、项目内容和数据结构。

后续新增页面时，优先复用现有 `PageShell`、`SectionHeading`、`btn`、`field`、`tabs`、`comment` 等组件和样式类。

## 2. 视觉方向

关键词：

```text
深色科技 / 工程感 / 高对比 / 大幅留白 / 嵌入式硬件主题
```

核心视觉规则：

- 主背景为近黑 `#0a0a0a`。
- 主强调色为红色 `#ff3b30`，用于编号、按钮、高亮和交互状态。
- 文字主体为高对比白灰，辅助文字使用低饱和灰。
- 标题使用 `Space Grotesk` / `Inter` 气质，正文使用系统中文友好字体。
- 技术编号、标签和辅助信息使用 `JetBrains Mono` / monospace。
- 首页使用 Three.js、OGL、Aurora、Ghost Fibers 等视觉组件营造硬件与信号流动感。
- 版心最大宽度约 1700px，适合大屏展示。
- 卡片和按钮有轻微玻璃感、细边框和柔和阴影。
- 动效以 reveal、hover、微位移和背景流动为主，避免喧宾夺主。

## 3. 响应式断点

当前样式断点：

- Desktop: 大于 `1080px`
- Tablet: `680px` 到 `1080px`
- Mobile: 小于 `680px`

移动端要求：

- 导航、标题、项目卡片和表单必须完整换行。
- 不允许文字溢出按钮或卡片。
- 视觉背景不能影响正文可读性。
- 视频区域保持稳定宽高，不能挤压布局。

## 4. 页面与路由

```text
/                首页
/experience      个人经历
/projects        精选项目
/projects/:id    项目详情
/strengths       个人优势
/comments        访客留言
/auth            登录 / 注册
/profile         个人主页
/admin           管理后台
```

## 5. 首页交互

- 顶部导航切换核心区块和独立页面。
- Hero 展示职业定位、主标语和主要行动入口。
- 点击项目卡片进入项目详情页。
- 滚动进入区块时执行 reveal 动画。
- 联系区展示电话、邮箱、GitHub 和微信等联系信息。

## 6. 项目详情页交互

- 根据 URL 中的 `id` 从静态项目数据查找项目。
- 未知 `id` 显示“未找到该项目”。
- 展示项目标题、英文名、定位、技术标签、演示视频、长介绍和核心实现。
- 外部仓库链接使用新标签打开。
- 底部展示当前项目留言。
- 返回按钮回到 `/projects`。

## 7. 登录注册页交互

- 登录与注册使用分段式标签切换。
- 注册需要昵称、邮箱、密码和确认密码。
- 密码和确认密码支持显示 / 隐藏切换。
- 两次密码不一致时给出前端错误。
- 登录或注册成功后跳转 `/profile`。
- 请求失败时展示后端错误信息。

## 8. 个人主页交互

- 未登录时提示先登录，不渲染资料表单。
- 支持上传头像，成功后刷新用户上下文。
- 支持修改昵称和个性签名。
- 支持修改密码，需要原密码和两次新密码。
- 保存成功显示确认提示，失败显示错误提示。

## 9. 留言区交互

- 未登录时显示“登录后参与留言”，并提供登录入口。
- 登录后可提交顶层留言。
- 登录后可点击“回复”展开回复表单。
- 提交成功后清空输入并刷新留言列表。
- 空状态使用友好文案。
- 前端按 `topic` 区分通用留言和项目留言。

## 10. 管理后台交互

- 非管理员只能看到无权限提示。
- 评论管理和用户管理使用标签切换。
- 删除评论后重新加载评论列表。
- 用户操作包括设为管理员、设为普通用户、封禁、解封、删除。
- 当前删除操作没有二次确认，这是待补强交互。
